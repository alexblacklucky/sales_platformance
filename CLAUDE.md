# CLAUDE.md — PLATFORMANCE / sales_platformance

Память проекта для Claude Code. Читается автоматически в начале каждой сессии.
**Прежде чем делать аналитику — открой `ANALYTICS_GUIDE.md` (там вся логика и история).**

## 🚀 Стартовый протокол — команда «Старт работы» / «Начиная работу, возьми все данные»
Когда пользователь в начале сессии пишет **«Старт работы»**, **«Начиная работу,
возьми все данные»** (или похожее), СРАЗУ выполни по порядку:
1. Прочитай этот `CLAUDE.md` целиком и `ANALYTICS_GUIDE.md` целиком.
2. Прочитай журнал работы: `worklog/STATE.md`, `worklog/BACKLOG.md`,
   `worklog/DECISIONS.md` и **последний** файл из `worklog/sessions/`.
3. Проверь актуальное состояние репозитория: `git log --oneline -10` и содержимое
   папки `analytics/` (какие месяцы уже собраны в Avito и Bitrix).
4. Кратко отчитайся пользователю: **чем занимались до этого** (что уже готово и
   залито в `main`), **что делаем дальше** (ближайший шаг — обычно новый месяц),
   и **какие файлы сайта будем менять** для этого шага.
5. Спроси, какие данные пользователь готов прислать (скриншоты Avito по авитологам,
   лист «по месяцам» с оплаченными клиентами, зарплаты), и жди их. Битрикс снимается
   вебхуком, Яндекс — через API, сам.
6. Заведи файл текущей сессии в `worklog/sessions/` и дописывай в него по ходу работы.

## 🏁 Протокол завершения — команда «Завершаем работу»
Когда пользователь пишет **«Завершаем работу»** (или похожее), СРАЗУ:
1. Допиши и закрой файл текущей сессии в `worklog/sessions/` (итоги, что осталось).
2. Обнови `worklog/STATE.md` — состояние на сейчас, дата, рабочая ветка, следующий шаг.
3. Обнови `worklog/BACKLOG.md` — сделанное в `СДЕЛАНО`, следующее в `СЕЙЧАС`.
4. Допиши `worklog/DECISIONS.md`, если появились новые правила/договорённости.
5. Обнови раздел «На чём остановились» в этом `CLAUDE.md`, если состояние поменялось.
6. Коммит → push в рабочую ветку → **PR → merge в `main`** (иначе следующая сессия
   журнала не увидит: репозиторий клонируется из `main`).
7. Коротко отчитайся: что сохранено и с чего начнём в следующий раз.

Подробности устройства журнала — в `worklog/README.md`.

Суть проекта в двух словах: помесячно собираем дашборды **Avito** и **Bitrix**
(+ «Общая аналитика») и встраиваем их в сайт-базу знаний; меняем файлы
`analytics/*.html` и `index.html`; деплой — только через PR в ветку `main`.

## Что это за проект
Статический сайт-база знаний отдела продаж PLATFORMANCE (агентство по продвижению
на маркетплейсах Avito / WB / OZON). Чистый HTML/CSS/JS, без сборки и бэкенда.
Живой сайт: **https://platformance-team.ru** (кастомный домен через `CNAME`,
GitHub Pages; старый адрес https://alexblacklucky.github.io тоже работает).

## Главные правила (не нарушать)
- **Деплой:** GitHub Pages отдаётся из ветки **`main`**. Изменения видны на сайте
  ТОЛЬКО после влития в `main` (PR → merge). Прямой push в `main` блокируется —
  лить через Pull Request.
- **Рабочая ветка:** задаётся окружением сессии, актуальная записана в шапке
  `worklog/STATE.md` (исторически была `claude/repo-exploration-lb95di`).
- **Журнал работы:** всё, что делаем, фиксируется в `worklog/` — читать при старте,
  обновлять по команде «Завершаем работу».
- После merge: подождать ~1–2 мин и обновить сайт жёстко `Ctrl+Shift+R`.
- Стиль всех дашбордов — светлая фиолетовая тема, шаблон `analytics/june.html`.

## Напоминания по расчётам (кратко, детали — в гайде)
- Bitrix `TOTAL` = сумма ВСЕХ колонок канбана; `MEET` = сумма 7 колонок
  (презентация, надо подумать, моросят, договор/счёт, провалена, БОМЖИК 2, успешна);
  `WON` = ручное число успешных сделок от заказчика (НЕ значение колонки).
- Встречей считается и видеовстреча, и телефонная продажа на 40–50 минут —
  часть клиентов принципиально не выходит на видео.
- Сделка засчитывается в `WON` по **оплаченному счёту**, даже если договор ещё
  не подписан и карточка висит в «Договор счёт».
- Контрольная проверка канбана: доля «Avito → Битрикс» должна быть **60–78%**.
  Вне коридора — скриншоты сняты без фильтра по источнику, пересобрать.
- Яндекс.Директ: контрольная проверка «клик → визит» должна быть **выше 90%**.
  **Число заявок берём только из Битрикса** (фильтр «Источник: CRM-форма») —
  цели Метрики врут в обе стороны. В дашборде обязательны и цена заявки,
  и её качество (таблица квалификации, целевые заявки).
- 🔴 **Каналы считаются раздельно** (раздел 0 гайда — главное правило).
  Расход Avito ÷ выручка с Avito; расход Яндекса ÷ выручка с Яндекса.
  Нельзя делить выручку одного канала на общий рекламный бюджет.
  Складывать можно только в блоке «Итого по отделу» и в P&L, с пометкой.
- В экономике реклама идёт двумя строками (Avito и Яндекс) с подытогом
  **«Маркетинг итого»**; доли расходов в приходе считаются от подытога,
  а окупаемость — по каждому каналу отдельно.
- Avito «Средняя конверсия в контакт» = контакты ÷ просмотры (вручную, с пометкой).
